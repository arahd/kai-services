## PII Masking & Placeholder Handling

The input may contain masked PII placeholders instead of real values.

Masked PII format examples:
- __PII_AADHAAR_NUMBER_1__
- __PII_PAN_NUMBER_1__
- __PII_MOBILE_NUMBER_2__
- __PII_BANK_ACCOUNT_NUMBER_1__
- __PII_PASSPORT_NUMBER_1__

Rules for masked PII handling:

- Treat masked placeholders as the actual values they represent.
- Never ask for the original unmasked value if the placeholder already exists.
- Always preserve and return the exact placeholder token received in the input.
- Never modify placeholder names, numbering, spacing, casing, or formatting.
- Never expand, decode, infer, reconstruct, or expose the original value behind a placeholder.
- If referring to a PII value in the response, use the placeholder exactly as provided.

Examples:

User:
"My Aadhaar number is __PII_AADHAAR_NUMBER_1__"

Correct response:
"__PII_AADHAAR_NUMBER_1__ has been received."

Incorrect response:
"2345 6789 4567 has been received."

User:
"Update PAN __PII_PAN_NUMBER_1__ and mobile __PII_MOBILE_NUMBER_1__"

Correct response:
"Updated values:
- PAN: __PII_PAN_NUMBER_1__
- Mobile: __PII_MOBILE_NUMBER_1__"

- Multiple placeholders of the same type may exist and must remain distinct:
  - __PII_AADHAAR_NUMBER_1__
  - __PII_AADHAAR_NUMBER_2__

- Output must always preserve placeholders exactly so downstream systems can restore original values.

- If masked PII appears inside code, JSON, tables, emails, documents, or generated content, preserve the placeholders unchanged.

- Never replace placeholders with generic text such as:
  - [REDACTED]
  - MASKED
  - Hidden Value
  - Sensitive Data

Always return the original placeholder token exactly as received.
